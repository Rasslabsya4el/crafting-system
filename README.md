# crafting-system

A crafting planner for Path of Exile: for a target item it finds the cheapest crafting policy and reports its cost and risk. Vocabulary is in [GLOSSARY.md](GLOSSARY.md); the design decisions are in [docs/adr/](docs/adr/).

## Install and test

Install [uv](https://docs.astral.sh/uv/getting-started/installation/), then, from the repository root (Windows or Linux):

```
uv sync
uv run pytest
```

uv downloads the pinned Python (3.14) by itself.

The naive crafter (`tests/naive_crafter/`) plays a guide's route by Monte Carlo without the planner's code and checks its cost against `risk.evaluate`; its long simulation runs on GitHub through the dispatcher, see `docs/ci.md` ("The naive crafter's long simulation").

## Directories

The data, cache and output directories come from, in order of priority: an environment variable, the config file `crafting.toml` at the project root (or the file named by `CRAFTING_CONFIG`, used instead), then the built-in default. All defaults are inside the project and git-ignored. Relative paths in a config file count from that file's directory; in environment variables and defaults, from the project root. An empty variable counts as unset.

| Directory | Environment variable    | Config key (`[paths]`) | Default        |
|-----------|-------------------------|------------------------|----------------|
| data      | `CRAFTING_DATA_DIR`     | `data`                 | `local/data`   |
| cache     | `CRAFTING_CACHE_DIR`    | `cache`                | `local/cache`  |
| output    | `CRAFTING_OUTPUT_DIR`   | `output`               | `local/output` |

## Plan a target

```
python -m crafting_system.cli examples/targets/r12-lightning-amulet.yaml
```

This reads the target, the pinned game data in the cache (`python -m crafting_system.data fetch` puts it there) and the price file in the data directory (`python -m crafting_system.prices fetch`, plus hand prices in `price_overrides.toml` beside it). It prints the cheapest policy as a short text tree (one block for each action you take, as the steps of the route page: what it costs, how often it is used and the odds of each outcome, the mean cost, the median cost and the cost 9 runs in 10 stay under, in Chaos with a Divine equivalent) and writes the same policy as JSON to `<output dir>/<target name>.policy.json`, or to the path given with `--json`.

- A target says how its start item is had, `start: bought` or `start: given` (OR-6; the key is required). A given item costs nothing, is never bought again (no `restart`) and the answer says so ("given: its cost is not counted, and the plan never buys another"); `--start-price` does not apply to it. The cost of a bought start item is the price stored under the key computed from the target, and a bought item without a price is an error that names the key: the target is the only description of the item (base, item level, influences, start item), and `targets/start_buy.py` computes its buy spec, trade query and price key from it (R12: `Paua Amulet, item level 84, fractured +(12-17)% to Lightning Resistance`). `python -m crafting_system.cli trade TARGET.yaml` prices it from the trade site. R13 and R04 hold poe.ninja stand-ins and V01 a hand price under their keys (issue #426); R08 and R09 hold the trade price of a normal base of item level 86 plus an Orb of Alchemy. A hand override wins; `--start-price CHAOS` (above 0) wins for one run. R03 and R06 are bought and have no price yet (the exact item has no listing, #483); J01 is given.
- A Harvest reforge costs its lifeforce (Lightning: 50 Primal Crystallised Lifeforce, rules registry `harvest_reforge.lifeforce_cost`) at the price in the price file. An action with a missing price is dropped and listed.
- The target may name the kinds of actions the planner may use with `actions: [alteration-orb, ...]` (the kind names are those of `crafting_system.actions.kinds()`); the plan is then the cheapest among those kinds and the report lists the others. R13 does, because a Chaos Orb on a belt makes the state space too big. The kind `fossil-set` (12,696 sets on boots) is a planner kind that is offered ONLY when a target names it there (R08 and R09 do); a target that names no `actions:` never pays for them. The Exalted Orb, the Orb of Annulment, the Fracturing Orb and the four corrupted essences (`corrupted-essence`) are offered the same way (R04 and R14 name them). A name in `actions:` may also be the label of one action (`Essence of Insanity`, `Bench craft Cannot roll Attack Modifiers`), which is then offered whatever the other filters say.
- The model offers, for the target's item class: a Chaos Orb, the Orbs of Transmutation, Alteration and Augmentation and the Regal Orb (for a normal or magic start item only), the Harvest reforge of Lightning, every essence of level 5 and up that gives a mod on that class, Remove Crafted Mods, the bench crafts whose mod counts toward one of the target's requirements (the other crafts are left out and listed: while every other action erases crafted mods, such a craft can never lower the mean; once an action keeps them, Augmentation or Regal, leaving them out is a choice and the report says so, because offering all of them makes the state space explode), and `restart`, buying the start item again at its price from any state but the start. Essences, crafts and restarts are named in a given route as the policy prints them (`Shrieking Essence of Spite`, `Bench craft +(15-25) to maximum Life`, `restart`); a bench craft is named with its roll range, so the tiers of one text are told apart.
- The benchmark routes R10, R11, R05, R13, R08, R09, R04 and R14 have their targets in `examples/targets/` and the guides' routes in `examples/routes/`. The benchmark route V01 (`examples/targets/v01-minion-helmet.yaml`, a Minion helmet with +1 to Level of all Minion Skill Gems and top Life) has no guide: its answer is the start the plan chooses, the vendor recipe's Magic helmet, and its entry in `benchmark.json` records the expected and the chosen start, every option's total and why the recipe wins (its target names the price file `tests/fixtures/prices/vendor-v01-2026-11-01.json`, so `benchmark` gives the same answer on every machine). A given route may also ask for `open_prefixes` / `open_suffixes` (at least that many free slots), when a bench action is offered. R24 and R07 (`examples/targets/r24-avoid-shock-boots.yaml`, `r07-minion-wand.yaml`, ticket #146) unveil a veiled mod; their routes ask `veil:` (the side of the veiled placeholder: `prefix`, `suffix`, `any`, `none`) and `offer:` (`none`, `drawn`, or `{shows: <requirement>, at: k}`: the k-th mod shown, the one `Pick k` takes, meets that requirement), when an unveil is offered. Their price file is `tests/fixtures/prices/veiled-r24-r07-2026-11-12.json`.
- **Memory Strands** are off unless the start item has them or the query turns them on: `memory_strands = true` under `[planner]` in `crafting.toml`, or `--strands` for one run (ADR-0040). A start item carries them as `memory_strands: 57` under `start_item` in the target (a whole number from 0 to 100, or the pasted line `Memory Strands: 57` of the game's item text) and turns the setting on by itself. With the setting off the report says `Memory Strands: not considered` on the line under the start item. Until the later tickets of batch B5 build the cut and the spend, a run with strands on stops with a message instead of an answer that would ignore them.
- **Recipe starts** (ADR-0059): the plan also tries the start items a vendor recipe can make (30% movement speed boots, flat damage weapons, chaos resistance jewellery, a spell-gem weapon, a Minion helmet) for a target that asks for the mod. Each is priced from its goods (the Normal base, the flasks, the Orbs of Augmentation and the quality gems, from the price file with hand prices on top; the gem lines are "Vendor recipe gems (fire, 40% quality)" and so on), each is planned with the same planner, and the answer is the cheapest total of start price and expected cost. The report lists every option tried and the recipes refused with the reason (no mod the target asks for, a cap below the asked tier, a missing price). A plan that starts from a recipe also opens with its own **first step** (step 1 of the policy and of the route page): what the vendor is handed (the Normal base, the flasks, the Orbs of Augmentation, the gems, each with its count and price), the recipes one by one with the mod and exact tier each gives, the Magic item that comes back and the start price. The same step is `start_options.first_step` in the JSON and row 1 of the route page (the buy-spec link is left out, since nothing is bought). `recipe_starts = false` under `[planner]` in `crafting.toml`, or `--no-recipe-starts` for one run, turns it off and gives the plan as it was before recipe starts.
- **A bought start with unknown mods** (ADR-0064): a bought Magic or Rare start item whose mods the target does not list is the item the market sells, not an item with no mods. A Magic one holds what an Orb of Alteration leaves on its base (1 or 2 mods at their game weights, the influence's mods included), a Rare one what an Orb of Alchemy leaves (4 to 6). The plan opens with that free draw (a **first draw, before S1** in the report, a step of its own on the route page) and chooses its first move on each outcome, so an Augmentation is used only where the item holds one mod. The price stays the price of the listing and a restart pays it again. A Normal start holds none, a start that lists a mod names its mods, and a given start is the item you hold, as written.
- `--verify` plays the policy on concrete items (`--runs`, default 10,000, about a minute on R12; `--seed`) and checks that the simulated mean agrees with the computed one within five standard errors. Its interval is a normal approximation, and the output states the smallest error of the computed mean the run can reject (about 5% for 10,000 runs, since a craft's cost is as spread as its mean; more `--runs` see smaller errors). Exit code 2 means it did not agree. For an approximate answer the lifted policy is played and its simulated mean, the cost 9 runs in 10 stay under and the average of the worst tenth are printed labelled "simulated, not certified"; it agrees when the simulated mean meets the certified interval.
- `--route ROUTE.yaml` evaluates a **given route** (a crafting route written as rules, see `examples/routes/r12-lightning-amulet.yaml`) exactly, at the same prices, and prints its success chance, mean cost, median cost and the cost 9 runs in 10 stay under next to the planner's, the first state where the two choose different actions, and any state the rules do not cover. The rules may only speak of what the compressed state holds today: rarity, corrupted, fractured mods, whether the item has a crafted mod, and the status of each requirement.
- `python -m crafting_system.cli benchmark [--out DIR]` runs the solver and the given route of every benchmark route that has both (today R12, R10, R11, R05, R13, R08, R09, R04 and R14, plus V01, which has no given route and records its expected start; R04 and R14 take the planner 10 to 30 minutes and 6 to 9 GB on the packed solver, so `benchmark` checks only their published odds unless it is given `--heavy`; their entries then also hold the guide's completed route (its rules plus the rules the guide does not have, which only keep the guide's own loop going and never restart where it could keep the progress, #599 and #628; `cli/_route.py`), whose mean is finite), checks the guide's published odds (a reading the guide gives no number for, like the top tier of R04's and R14's forced Exalted Orbs where the guide's 100% is of the family, is listed as "our odds" with no number to differ from, #599), and writes `benchmark.json` with the machine (OS, CPU, Python, commit) and run times to the output directory. It records the results and never fails on them. It compares the planner with the guide on both sides: beside "the planner is not dearer" each route with a given route lists every state of the planner's main line where the guide does something else (what the item is, what each side does, the chance of visiting the state under each policy; the top 10 by chance, the rest counted), prints the ratio planner mean / guide mean, and adds a "needs a human" row when that ratio is below `review_ratio` in the `[benchmark]` table of `crafting.toml` (default 0.5; a prompt to look, never a cut of the search); a route a person has taken apart carries a verdict (`cli/_benchmark_verdicts.py`, #634) and prints `reviewed: real find (#591), ratio at review 0.057` until its ratio moves by more than `review_tolerance` (default 0.2 of the ratio at review), its target or route file text changes, or the planner's first divergent action changes, when it prints "NEEDS A HUMAN AGAIN" with the reason; under the row the chance and the cost of one use of the planner's action and the guide's at the first divergence are told (#617); the same data is in `benchmark.json`. `.github/scripts/benchmark_routes.py R12,R10 OUT_DIR` runs `benchmark --heavy` on the named routes only, so that a heavy run can split the routes over its runners.
