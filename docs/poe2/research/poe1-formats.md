# How the PoE1 knowledge is stored, and the PoE2 mirror of each format

Date checked: 2026-11-24, on `main` at 58bd5ad7. This is the inventory step 1 of the PoE2 research asked for: every kind of PoE1 knowledge in this repository, its file type and fields, an example path, and where its PoE2 counterpart lives on this branch.

## Inventory

| Kind of knowledge | PoE1 file type and fields | PoE1 example | PoE2 mirror (this branch) |
|---|---|---|---|
| Mechanics claims (the rules registry, ADR-0004) | YAML, one file per mechanic family, a top-level `rules:` list. Required fields: `id` (`<family>.<name>`, lowercase snake case, family = file name), `statement`, `source_kind` (`official`, `wiki`, `datamined`, `experiment`, `coe`, `owner`), `url`, `quote` (at most 400 characters), `patch_verified` (three or four numbers), `date_checked`. Optional: `value` (any YAML value, frozen), `history` (list of `held_until`, `source_kind`, `url`, `quote`, optional `statement`, `value`), `approximate: true` with `approximate_reason`, `page_statement`, `page_source`. No other key is allowed. A file comment names the family and the research ticket. | `src/crafting_system/rules/claims/chaos_orb.yaml` | `docs/poe2/claims/<family>.yaml`, the same schema exactly, so that a port copies them into the package. `patch_verified` is the PoE2 version (`0.5.5.10`, `0.4.0`). Validated with the PoE1 loader: `uv run --no-sync python -c "from pathlib import Path; from crafting_system.rules.registry import load_registry; print(len(load_registry(Path('docs/poe2/claims'))))"` |
| Confidence and open questions of a claim | Not in the YAML (no key allows it): a low-confidence claim is `approximate: true`; open points live in the research note of the ticket and in GitHub issues (the owner's in-game list #182). | `docs/research/2026-10-31-corruption.md` (sections "Open") | `approximate: true` for medium or low confidence; the per-family note `docs/poe2/notes/<family>.md` holds confidence per claim id and the open questions ("Needs an in-game check"). |
| Research notes | Markdown under `docs/research/`, named `YYYY-MM-DD-<topic>.md`: ticket link, date checked, patch, the answer first, tables with source keys, a source list, open points. Sidecar data next to it (`.json`, `.py`, folders of samples). | `docs/research/2026-10-30-crafting-methods-inventory.md` | `docs/poe2/research/*.md` (the raw research per area, with every source), `docs/poe2/notes/*.md` (per family). |
| Methods inventory and batches | One research note with one row per method (`M-xx`: method, what it does, inputs, status with source keys, scope, batch), plus ADR-0013 for the batches B1–B9 and OR-37 for the beta scope. | `docs/research/2026-10-30-crafting-methods-inventory.md` | `docs/poe2/METHODS.md`: rows `P2-xx` with preconditions, outcome distribution, cost unit, proposed batch. |
| Decisions | ADRs in `docs/adr/NNNN-<title>.md`: a title sentence, the decision, "Origin", "Considered options", "Consequences", dated amendments. | `docs/adr/0003-raw-game-data-from-repoe-fork.md` | `docs/poe2/adr/P2-NNNN-<title>.md` (proposals only: no PoE2 decision is the owner's yet). |
| Owner rules | `docs/owner-rules.md`, `OR-n` entries with Example, Counter-example, Reason, Source. | `docs/owner-rules.md` | None: the owner has given no PoE2 rule. The port plan lists which OR rules carry over. |
| Terms | `GLOSSARY.md`: `**Term**:` then a definition and `_Avoid_:` synonyms. | `GLOSSARY.md` | `docs/poe2/GLOSSARY-POE2.md`, the same form, PoE2 terms only. |
| Raw game data | repoe-fork JSON files pinned by version, commit, sha256 and size in `src/crafting_system/data/PIN.json`; fetched by `python -m crafting_system.data fetch` into `$CRAFTING_CACHE_DIR/repoe-fork/<version>/`; never committed (ADR-0003). Files: `mods.json`, `base_items.json`, `essences.json`, `fossils.json`, `crafting_bench_options.json`. | `src/crafting_system/data/PIN.json` | `research/poe2/data/PIN.json` + `research/poe2/data/fetch_poe2.py` (standard library; cache `$CRAFTING_CACHE_DIR/repoe-fork-poe2/<version>/`). PoE2 has no `essences.json`; the essence, tiered currency, socketable and other tables come from repoe-fork/dat-export CSVs, pinned in the same file. |
| Derived data excerpts | Small committed fixtures for tests (`tests/fixtures/`), JSON pools next to research notes. | `docs/research/2026-10-31-corruption-implicit-pools.json` | `research/poe2/data/derived/*.md` (readable extracts, generated by `derive_tables.py`) and `research/poe2/data/trade-api-2026-11-24/*.json` (the official trade site's lists). |
| Prices | A dated local file (ADR-0007) from poe.ninja or the trade site; `src/crafting_system/prices/`. | `tests/fixtures/prices-*.json` | No price file yet; the data plan names the sources and API shapes (`docs/poe2/DATA-PLAN.md`). |
| Action classes | Python, one class per method under `src/crafting_system/actions/`, reading rules by `get_rule("<id>")`. | `src/crafting_system/actions/chaos.py` | No code: `docs/poe2/PORT-PLAN.md` maps each class to its PoE2 counterpart. |
| Targets and routes | YAML under `examples/` and `src/crafting_system/data/targets`; a target file has a top-level `requirements:` key. | `examples/targets/*.yaml` | None. (No YAML on this branch has a top-level `requirements:` key, because `tests/test_every_target_file_parses.py` parses every such file in the repository.) |

## Paths chosen and why no PoE1 test reads them

- `docs/poe2/` for notes, claims, the glossary section, ADR-style proposals, the methods catalogue, the data plan and the port plan; `research/poe2/data/` for the pin, the fetch and derive scripts, and the committed snapshots.
- Checked on 2026-11-24 in `tests/`: no test globs `docs/` or `research/` as a whole. The tests that read docs name single files (`docs/owner-rules.md`, three ADRs, files under `docs/research/`), and the tests that import from `research/` add `research/312` and `research/376` only. Two repository-wide scans exist and are respected: `tests/test_every_target_file_parses.py` (every `*.yaml` with a top-level `requirements:` key is parsed as a target: none here has one) and `tests/test_no_absolute_paths.py` (every tracked code or data file, `.py .json .yaml .txt ...`, must hold no absolute path: every file under `research/poe2/` and `docs/poe2/` was scanned with the same detector before each commit).
- The PoE2 claims are not in `src/crafting_system/rules/claims/`, so the PoE1 registry and `get_rule` never see them.
