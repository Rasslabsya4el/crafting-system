# Prices: Chaos Orb unit, a dated local price file, every source tried before an action is dropped

Costs are in Chaos Orbs, with a Divine Orb equivalent in reports; time and clicks cost nothing. The solver reads prices only from a dated local price file, so a query is repeatable and never waits on the network; fetchers are separate tools that write that file, and any line can be overridden by hand.

poe.ninja is the price source. When a price is missing, the fetchers look further before giving up: price history in other time ranges on poe.ninja or poe.watch, and for buy actions the official PoE trade API through an existing wrapper rather than our own search-filter code ([Price sources: price history and the trade API](https://github.com/Rasslabsya4el/crafting-system/issues/13) names the endpoints and the wrapper). Only when every source fails is the action unavailable to the solver, and the report lists what was dropped for lack of a price. A price file older than 7 days gives a warning, not an error.

The fallbacks are built ([Prices: bases, beasts, poe.watch and previous-league fallbacks](https://github.com/Rasslabsya4el/crafting-system/issues/40)). Bases (per item level and influence) and beasts come from poe.ninja's stash overview; a line with fewer than 5 observations is not priced, only reported. For a wanted name without a usable current price the fetcher tries, in order: poe.ninja history of the same league, poe.watch for the current league, the previous league at the same league age, Standard. Each price found is stamped with its source, league and date and printed as a warning; the last two are a different economy and say so. The trade-API query keeps only listings from the last week by default, so an old listing cannot set a floor price. (**Replaced: the query sets no listing-age window; see "Amendment: no listing-age window" at the end.**)

A fetch skips a wanted name that a hand override or a trade-API price of the same league already covers, so it spends no request on it ([Buy spec: name a mod by stat text or id, not only family](https://github.com/Rasslabsya4el/crafting-system/issues/47)). A buy-spec mod is named by repoe family, by mod id or by exact English stat text; naming a family whose mods have different texts is refused.

The open points of those tickets are closed ([Prices: aged trade prices, canonical names, partial fetch failures](https://github.com/Rasslabsya4el/crafting-system/issues/84)). A trade-API price ages like the file: older than 7 days (counted from the date of its run), it no longer covers its name, so a fetch treats the name like any other wanted name; the price stays in the file and `fetch` and `check` flag it stale until the next `trade` run replaces it. Price names are put in canonical form (influences in game order) when the price file is read, as hand overrides already are, so a price stored under another spelling is found; two names that become one are an error. Only the four exchange overviews (Currency, Fossil, Resonator, Essence) must answer for a fetch to write a file; a failed Beast or BaseType overview warns, keeps the old poe.ninja prices of that category (same league; a stash price carries its category in `detail`, a price written before that is not kept) with a note of the fetch they come from, and lets the rest finish.

The trade-API fetcher runs only when the owner starts it, never unattended: that is the safe reading of GGG's developer documentation and Terms of Use (main chat, 2026-10-30, in [Owner decisions on B1 mechanics no source or Craft of Exile settles](https://github.com/Rasslabsya4el/crafting-system/issues/28); the owner may widen it).

Origin: [Design grill round 1: foundations](https://github.com/Rasslabsya4el/crafting-system/issues/2) Q5, [Design grill round 3: modules, verification, process](https://github.com/Rasslabsya4el/crafting-system/issues/4) Q21 (amended by the owner).

## Amendment: a scheduled refresher keeps the trade prices fresh ([#337](https://github.com/Rasslabsya4el/crafting-system/issues/337), owner, 2026-11-01)

The rule above ("the trade-API fetcher runs only when the owner starts it, never unattended") is widened for **one component only**: a scheduled price refresher. The user never refreshes anything. The refresher is a service component of the product (a website with full uptime), not a CLI step. It sends anonymous requests (no account, no session cookie) at an interval, within a request budget per interval, through the existing client and limiter in `prices/trade_http.py` (it reads the `X-Rate-Limit-*` headers of every response, which state each window's limit and current use; it keeps a configurable margin below every window, honours `Retry-After`, backs off on a 429 and stops on 401, 403 or a Cloudflare page; it logs the limits it observes so they can be checked over time, and it never probes by hitting a limit). It writes the dated price file; the solver still reads only that file and never waits on the network. It asks only for the candidate start items that targets need (ADR-0061), not for every state. **Risk:** GGG's developer documentation does not list the trade endpoints and says that reverse-engineering endpoints outside it is against the Terms of Use (section 7i), so unattended use may be refused or the IP restricted; the owner accepts this for the refresher.


The market rule and the recorded states ([#355](https://github.com/Rasslabsya4el/crafting-system/issues/355), owner answer Q4 of #337): a trade search makes a price only when the site has at least 10 listings (a setting, `--min-listings` / `min_listings`) and at least 3 of the fetched ones can be priced; the price is the mean of the 5 cheapest usable listings. Otherwise the search is kept as a recorded state in the price file's `markets` table with its listing total, usable count and date: `thin` (listings, but too few) or `none` (the site answered total 0). Neither is offered, and either replaces an older quote of the name. A quote, a `thin` or a `none` record is fresh for 7 days (counted from its date); an older one is not offered and the refresher asks again. `prices.trade_market.offer` answers, per name, whether it is offered and which rail (listing count, age) cut it and at what value.

## Amendment: no listing-age window ([#406](https://github.com/Rasslabsya4el/crafting-system/issues/406), owner rule OR-7 in [`docs/owner-rules.md`](../owner-rules.md), 2026-11-06)

The sentence above that the trade-API query "keeps only listings from the last week by default" is replaced. By the owner's rule (OR-7, from the R10 page of 2026-10-31, built by [#133](https://github.com/Rasslabsya4el/crafting-system/issues/133)) the query asks for **Instant Buyout** listings only and sets **no listing-age window**: an instant-buyout listing's price stands however old the listing is, and the price is the mean of the cheapest few (OR-8, five by default). The code already does this (`prices/trade_query.py`: `DEFAULT_STATUS = "securable"`, `DEFAULT_INDEXED = None`; `prices/trade_pricing.py`: the mean of the `k` cheapest); `--indexed` narrows the window only when a person asks for it. The 7 days of this ADR remain the age of a price in the file (a quote, a `thin` or a `none` record older than 7 days is not offered and is asked again), which is a different thing from the age of a listing. Where no trade price exists, a poe.ninja row may stand in only as a marked fallback ([ADR-0061](0061-the-planner-chooses-its-start-base-and-a-fractured-start-from-a-priced-list.md), decision 2); that the planner and the route page do so is open work of #406, not a claim of this amendment.

## Amendment: a price carries where it came from, and only a deep enough one is a plain fact ([#616](https://github.com/Rasslabsya4el/crafting-system/issues/616), main chat decision of 2026-11-07, OR-7, OR-8, OR-12, OR-23)

A price entry carries its **provenance as data**, not in the free `note` (`prices/provenance.py`, the `provenance` block of an entry in the price file): the source (poe.ninja exchange, poe.ninja daily rows, an earlier league or Standard, poe.watch, the trade site's instant buyout, a hand price, a default), the league and the UTC date of the reading, the **depth** and the **item** the price was taken for. The depth of an exchange line is the units traded on the day (poe.ninja's `volumePrimaryValue`, in Chaos, over the price); of a trade price the units held by the listings the mean is made of (the cheapest five); of a stash line poe.ninja's observation count. A price taken for a wider item says which and, when the exact item has listings of its own, how many and what they ask.

**The rule** (`prices/price_marks.py`): a price is a plain fact only when it is of today's league, of the exact item, and deep enough for what the plan buys, that is its depth in units is at least the units the plan's policy expects to use of it (the expected visits of the policy times the units an action takes, `risk.expected_totals`). Any other price is an approximate input (OR-23) listed with its reason: "price on N units", "previous league's price", "price of a wider item; the exact item has K listings at P". There is no fixed cut that drops a route (OR-12): a price on few units is kept, marked, and the plan is solved with it. A hand price and a default are the user's and the model's own numbers and are not marked; an entry written before this amendment has no provenance and is judged on its source alone (a previous league's price is still marked, a depth is not judged).

**The best estimate.** For a wanted name whose exchange line is thin or missing, `fetch --trade-below UNITS` reads the trade site's bulk-exchange offers of the same day (anonymous, the mean of the cheapest five offers per unit) and keeps the deeper of the two readings; the other stays in the provenance (`other`). A reading of the league being priced always beats one of an earlier league. A name is left unpriced, and the answer's limit says so, only when no source has any evidence. The trade book is read as every trade price is (OR-8): the mean of its cheapest few offers, however many it holds, and its depth is the units the offers priced hold, so a book of three offers on 94 units beats a line on 0.5 units; no count of offers decides. A price with no recorded provenance (a file from before this amendment, a hand-written one) is an approximate input too, never a plain fact: "where this price comes from is not recorded". A fetch that a blocked trade site or a spent request budget stops writes the poe.ninja prices anyway, marks the names it did not read (`trade_unread`, printed as "the trade offers beside it were not read" when the plan buys more than the price's depth), lists them in its output and exits 1.

The page and the text report list every price the policy buys with, its source and its marks (`cli/_price_marks.py`); the marked ones are also in "Approximate inputs".
