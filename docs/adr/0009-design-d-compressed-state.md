# The compressed state is design D, with exact merges only

The solver's compressed state keeps, for each target mod, an exact status: absent, present but below the required tier or roll, or present and passing. Junk is a multiset of family types: families that every enabled action treats alike are merged and counted, not identified. Exceptional families that no family type covers stay explicit. Flags carry rarity, fractured and crafted mods, metamods and influence. Transition kernels are cached by pool signature, so equal signatures share one kernel.

The reason is the trade-off measured in [state compression research](../research/2026-10-30-2-state-compression.md): tracking every blocked family by identity is exact but explodes (about 1 million core states at 10 families per side, 370 million at 40); counting junk by tag class is small but not exact, because two junk mods with the same tags can block different families and so change the pool differently. Design D is close to the class-count size and stays exact.

v1 allows only exact merges in the exact state. An approximate merge is allowed only as a coarse state with an optimistic and a pessimistic model, which certify the answer's error, and the answer is marked approximate when the exact state would not solve in about a minute ([ADR-0023](0023-approximate-answers-as-two-bounds-around-one-policy.md), map [Crafting system v1](https://github.com/Rasslabsya4el/crafting-system/issues/1), "Not yet specified").

## Widening for B1 ([Compressed state for essence reforges and bench crafts](https://github.com/Rasslabsya4el/crafting-system/issues/59))

The non-fractured mods are kept as slots (side, kind, what the mod gives each requirement) once an enabled action reads them. The kind is a family type for the families that every enabled action treats alike, and the family itself where one does not: today only the bench, whose craft is refused when a family on the item clashes with its mod, so the families of the enabled crafts are told apart. With only the erasing rerolls (Chaos Orb, Harvest reforge, essence) enabled no slot is kept besides the crafted ones, and the state is as small as before. Crafted mods are always slots, by their canonical mod id. An action that adds or removes one mod refines the family types by pool weight; the next section says how.

## Widening for fossil reforges ([Compressed state and action set for fossil reforges](https://github.com/Rasslabsya4el/crafting-system/issues/62))

A resonator is an erasing reroll like the Chaos Orb, so the state does not change: the junk is not kept (unless another enabled action reads it), the fractured mods stay, the status is per leaf. What changes is the pool. The fossils' factors and blocks are already in the weights of the pool that `ApplyFossils.outcomes` builds, and the family types of the signature carry the weights, so **kernels are keyed by pool signature and not by the set of fossils**: two sets whose pools are equal (a fossil that touches no mod of this base, two fossils that give the same weights, a Chaos Orb) share one kernel, and a set with one pool and no Fractured Fossil has the signature of that pool.

A **mixture** (Tangled: up to 420 pools; Glyphic: one pool per forced mod) is solved exactly, part by part: each part is cached by its own signature and the kernel is the sum of the parts weighted by their probability. Tangled sets are therefore not left out; they cost one distribution for each pool that is not already cached (6 to 60 s a set on real boots, about 0.6 s per new pool).

A **Fractured Fossil** fractures one finished mod, so the state must record which one (the fractured mod stays through every later reroll and its family leaves the pool). The mod is stored like any fractured mod, by its canonical id. The exact engine does not track which family was drawn, only how many of each class, so the joint of the fractured mod and the rest is built from one run per family type with that type's mods marked in the label: the families of a type are interchangeable, so each of them is the fractured one with an equal share. That multiplies the cost of a pool by the number of family types (0.5 to 25 s a set on real boots, median about 4 s, against 0.1 to 1 s for the same set without the Fractured Fossil); the result is cached by pool signature and the label of the forced mod. A forced mod (Hollow, Glyphic) takes part in the choice and, when it is the one fractured, leaves the slots. Bound-based pruning of the action set (the map's "bound-based action pruning") is what keeps this affordable; it is its own ticket.

## Widening for the magic-item orbs ([Compressed state for magic items and added mods](https://github.com/Rasslabsya4el/crafting-system/issues/65))

An Augmentation or a Regal Orb keeps the mods the item has and draws one more, so the junk is read: a family on the item leaves the pool, and the weights that remain decide the draw. An action says so with `Reads.adding()` (`pool_weight`): the junk is kept as slots, and the families that no enabled action tells apart by name get a kind that stands for their **family type**: the side, and the sorted (what each mod gives the goal, weight) of the family's mods in the pool of an empty rare item. Fire, Cold and Lightning Resistance on a belt with no mod asked of them and equal weights are one type; a family the goal asks for, or one with another weight, is another. The kind is the number of the type (`~0`, `~1`, ..., sorted, so it is the same on every run), a family named by a bench craft still keeps its own name, and a state holds a multiset of types per side. The pool of a later draw is the pool of the empty item without the families on the item, so its multiset of family types is the whole multiset minus the junk's, and two junk families of one type leave the same pool: the merge is exact. A representative item for a kernel takes, for a slot of a type, any family of that type that is not already taken.

Magic items need no new field: the rarity is in the flags, the capacity (one prefix and one suffix, three of each for a rare) is in the free slots the pool signature already holds, and a Regal Orb changes the rarity of the retained item, which the kernel reads back. A Transmutation, an Alteration, an Alchemy and a Scouring erase the junk (`Reads.nothing()`): the first three redraw it, a Scouring leaves the fractured mods and the rarity they allow (normal, magic, rare for none, one, two or more), so none of the four adds a slot to a state that does not need one. The cost is one kind per family type instead of one per family: on route R13 (T1 life, two T1 resistances, a crafted damage mod; Leather Belt, item level 86) the four orbs of the route reach 1,507 states with family types and 1,681 with every family told apart, and compute 117 distributions with 184 cache hits.
